Status: Awaiting review
Scope: Phase 1 (quote engine, customers, projects, documents)

## 1. Direction

Estimating is desk work, not site work. The visual language comes from drafting — blueprints, spec sheets, graph paper, quote pads, red markup pencil — not from hard hats and hi-vis. That vernacular is more specific to what this software actually does, and it is a far less exhausted well than construction-safety iconography.

Three qualities the interface has to deliver, in priority order:

1. **Legible under bad conditions.** Direct sun on a phone, a dim job trailer, a laptop screen at a client's kitchen table. High contrast, no low-contrast grey-on-grey, no thin hairline type at small sizes.
2. **Dense without being cluttered.** A quote is forty line items. Density is the feature; the design must support scanning a column of figures, not chunk everything into cards.
3. **Trustworthy with money.** Figures align. Totals never surprise. Nothing important is hidden behind a hover.

### 1.1 Reference material assessed

Two Stitch design systems were supplied — "Atelier Precision" and "Modern Industrial Precision" — along with mobile mockups of a broader product.

**Taken from Modern Industrial Precision:** information density, 4px corner radii, structural 1px borders in place of drop shadows, tabular numerals, 48px field touch targets, high-contrast surfaces.

**Taken from Atelier Precision:** restraint, whitespace discipline, and the idea of one dominant figure per view.

**Rejected, with reasons:**

| Rejected | Why |
|---|---|
| Safety-orange as system default | The most predictable construction cliché. Accent is a white-label token; the default should not be the obvious choice |
| Pill badges throughout | Reads as consumer app; poor at conveying rank or state in a dense table |
| Uppercase mono micro-labels above every block | Decorative use of monospace. Monospace here is for numeric alignment, which is functional |
| Cards nested three deep | Card-in-card-in-card defeats the density the same document asks for |
| Safety scores, crew streams, retainage dashboards, draw schedules | Phase 3–5 or out of scope entirely. The mockups depict a much later product |

Note for future reference: in both supplied files the YAML colour tokens (Material-3 blues, `surface: #f8f9ff`) contradict the prose palette in the same document (slates and oranges). They were generated independently. Neither was adopted verbatim.

## 2. Tokens

### 2.1 Colour — adopted from Budget Tracker

The existing Budget Tracker project (`Documents/Budget Tracker`) carries a mature, dual-theme token system in `src/app/globals.css`. **That vocabulary is adopted wholesale.** Inventing a parallel set of names for the same concepts would mean maintaining two mental models across two codebases the same person maintains.

| Token | Light | Role |
|---|---|---|
| `--canvas` | `#f5f5fa` | Application background |
| `--surface` | `#ffffff` | Cards, tables, panels |
| `--surface-2` / `-3` | `#efeff7` / `#e7e7f3` | Recessed and layered fills |
| `--line` / `--line-strong` | `#e2e2ef` / `#cfcfe4` | Hairlines; section and table edges |
| `--ink` | `#16162b` | Primary text |
| `--muted` / `--subtle` | `#5a5a72` / `#6e6e88` | Secondary text. Contrast floor; nothing lighter carries meaning |
| `--accent` (+ `-hover`, `-fg`, `-soft`, `-soft-fg`) | `#4b49d6` | Primary action, active state. **Per-tenant override** |
| `--positive` (+ `-soft`, `-soft-fg`) | `#0b7a52` | Healthy margin, accepted, paid |
| `--negative` (+ soft pair) | `#c2352b` | Negative margin, declined, expired |
| `--warning` (+ soft pair) | `#9a5b00` | Pending, expiring soon |
| `--info` (+ soft pair) | `#1d63c7` | Informational, links |
| `--money-positive` / `--money-negative` | aliases | Signed amounts |
| `--elev-flat` / `-card` / `-pop` | — | The three elevation steps |

The white-label accent (section 2.1 of the architecture spec) maps to the `--accent` family. A tenant sets one colour; the hover, foreground, and soft variants derive from it.

Every status colour is paired with a text label or icon. Colour never carries meaning alone — a red figure is also signed, a green chip is also worded.

**Dark mode is in scope**, reversing an earlier call in this document. Budget Tracker already ships a complete dark palette under `[data-theme='dark']` and a working theme toggle, so the marginal cost is small, and a truck cab at 6am is a real use case.

### 2.2 Type

The one deliberate departure from Budget Tracker. That is a personal finance tool; this is a customer-facing product that also prints contracts, so it earns its own typographic voice.

IBM Plex superfamily. Engineering-drawing lineage, genuinely tabular figures, open licence, and self-hosted — the app runs on our own box, so there is no CDN constraint and no external font request.

| Face | Role |
|---|---|
| **Plex Sans** | All interface text |
| **Plex Mono** | Numerals in tables, money figures, document numbers, rate codes — **only** |
| **Plex Serif** | Customer-facing PDF headings only |

Plex Mono is used for column alignment, which is a functional requirement in a financial table. It is never used for labels, eyebrows, or decoration.

Plex Serif appears exclusively in generated documents. The quote a customer receives should read as a contract, not as a screenshot of software.

Scale, 1.25 ratio, tightened tracking at display sizes:

| Step | Size / line-height | Weight | Use |
|---|---|---|---|
| `display` | 30 / 36, `-0.02em` | 600 | The one dominant figure on a view |
| `title` | 20 / 28 | 600 | Screen and panel titles |
| `heading` | 16 / 22 | 600 | Section and group headers |
| `body` | 14 / 20 | 400 | Default |
| `small` | 13 / 18 | 400 | Table cells, metadata |
| `micro` | 11 / 14, `0.04em` | 600 | Status chips only |

All numeric cells set `font-variant-numeric: tabular-nums`.

### 2.3 Space, shape, elevation

8pt base, 4pt for micro-adjustment. Gutters: 16px mobile, 24px tablet, 32px desktop.

Radii: **4px** controls and rows, **6px** panels and sheets, **0** on table cells and the sticky sum bar. No pills.

Elevation is tonal and structural, not atmospheric. Panels are `--surface` on `--canvas` with a 1px `--line` border. Shadow is reserved for genuinely floating layers and uses the adopted steps: `--elev-card` for panels that need lift, `--elev-pop` for bottom sheets, popovers, and modals.

Touch targets: 44px minimum, 48px for anything used on site.

## 3. Responsive strategy

**Full capability parity**, including the quote worksheet on a phone. Desktop is a table; mobile is a card list. Two visual treatments, deliberately different — which is what was asked for.

**One DOM tree, reflowed by CSS. Not two render paths.**

Budget Tracker already settled this and recorded why, in `src/components/ui/Table.tsx` (ruling R5): branching the render to a bespoke card list on phones means every checkbox, button, and input a page renders exists twice in the document. That doubles the matches for the `getByLabelText` and `getByRole` queries the test suite depends on, making roughly 25 test files ambiguous rather than merely wrong. One tree that CSS reflows keeps every query pointed at exactly one node, at every width, for free.

So the two distinct views are real, and they cost one render path. The mechanism exists there and is reused verbatim: `TableWrap`'s `responsive` prop adds `data-table--stack`, and a media query below `sm` hides `thead`, turns each `tr` into a card, and reprints each cell's column name from its `data-label` attribute.

Two supporting props from the same component, both with reasons documented in place after being learned the hard way:

- `fixed` opts into `table-layout: fixed` with a `<colgroup>`. Required for any table whose rows carry controls — auto layout hands width to the longest text and leaves inputs and buttons fighting over the remainder.
- `minWidth` is **mandatory** whenever `fixed` is set. A fixed-layout table is `width: 100%` and can never overflow, so `overflow-x-auto` never engages; narrow screens then collapse elastic columns to nothing, which once rendered merchant names one character per line.

| Breakpoint | Shell | Worksheet form |
|---|---|---|
| `< 640px` | Bottom tab bar, 5 destinations | Stacked cards via `data-table--stack`, sheet editor, collapsed sum bar |
| `640–1279px` | Collapsed icon rail | Table with `colgroup`, inline editing, full sum bar |
| `>= 1280px` | Expanded rail | Full table, inline editing, full sum bar |

Layout is driven by container width, not device sniffing. A tablet in landscape gets the desktop treatment because it has the room.

The worksheet is an editing surface, not a read-only ledger, so the stacking pattern needs three additions it does not need for a ledger. The review confirmed the single-tree approach is sound **on these conditions**:

1. **Explicit ARIA roles.** `role="table"`, `role="row"`, `role="cell"` on the elements. Changing a `<tr>` to `display: grid` strips the implicit table semantics in Safari, so a screen reader stops announcing rows and columns at exactly the width where the layout is least self-explanatory.
2. **`position: sticky` on cells, not on `<tr>`.** A sticky row does not work once the row is a grid; the group band has to stick via its cells.
3. **Below `sm` the inline inputs are `readOnly`, and the row tap opens the sheet — which is the only editor at that width.** Two live editors for one value, one of them in a 40px-wide stacked cell, is how a quantity gets changed by accident on a phone in a truck. The inputs still exist once in the DOM; below `sm` they render as values and delegate editing.

The inputs exist once, in one place, at every width.

## 5. The quote worksheet

Boldness is spent here. Every other screen is quiet.

The metaphor is an **estimating worksheet**, not a card kit: collapsible groups, real rows, aligned figures, and a sum bar pinned to the bottom edge the way a spreadsheet pins its totals.

Editing is inline. Tab moves across a row, Enter commits and moves down, so a full quote can be adjusted without touching the mouse. Every figure recalculates on commit, not on keystroke.

The **margin gauge** in the sum bar is the only moving colour in the interface. It shifts `--positive` to `--warning` to `--negative` against the target margin on the rate card. It is the single element the owner watches while working, and the reason cost sits on the same line as price.

Line items are two-line blocks: description on the first, `code · qty × rate` on the second with the line total right-aligned in Plex Mono. Group bands stick to the top while scrolling their section so the owner always knows which trade he is in.

Tapping a line opens a **bottom sheet editor** with 48px numeric fields, `inputmode="decimal"` so the phone shows a number pad, the unit label rendered beside the field, and a live line total above the keyboard.

The sum bar collapses to one line — total plus margin chip — and expands to the full tax breakdown on tap. The scope inputs collapse into a summary line that opens a sheet.

Adding a line uses a search-first picker over the rate card, not a long select.

### 5.3 Present mode

A single toggle that hides cost, margin, internal notes, and the rate codes.

The reason is physical: he shows quotes to customers on his own screen, at their kitchen table. Without this, turning the laptop around shows the client his cost and his margin. With it, the same screen becomes a clean customer-facing summary.

It is a view state, not a permission — it changes nothing in the data and is one tap to enter and leave. It persists per device so the phone he hands across the table stays in Present mode.

## 6. Components

Hand-rolled primitives in `src/components/ui/`, following Budget Tracker's convention rather than pulling in shadcn — that project's primitives are proven, documented in place, and already match the token system adopted above.

**Reused directly** (same names, same contracts): `Money`, `TableWrap`, `AmountCell`, `ListRow`, `StatTile`, `MetricCard`, `EmptyState`, `Pill`, `ProgressBar`, `PageHeader`, `SectionHeader`, `RowDialog`, `RowMenu`, `Notice`, `Button`, `Card`, `AppShell`.

`Money` is worth noting: it takes integer cents, colours by sign, and sets tabular figures, with a `plain` variant for magnitudes that are not signed amounts — a quoted total is not good news or bad news, so it should not be painted green.

**New for this product:**

- **Data table** — 44px rows, 1px `rule` dividers, `accent-wash` on the selected row, right-aligned tabular figures, sticky header, sticky group bands.
- **Sum bar** — pinned to the bottom edge, `sheet` on a `rule-strong` top border, square corners. Collapsed variant on mobile.
- **Margin gauge** — segmented bar, eight cells, colour by band against the rate-card target. The one animated element; respects `prefers-reduced-motion`.
- **Status chip** — 4px radius, `micro` type, tinted background with a matching 1px border, always paired with a word.
- **Sheet editor** — mobile bottom sheet with a grab handle, large numeric fields, live line total.
- **Empty states** — every list ships one that names the next action. "No quotes yet. Start one from a customer, or create a customer first."
- **Money input** — right-aligned, Plex Mono, unit suffix, no spinner arrows, selects all on focus.

## 7. Document design

Generated PDFs are a separate visual system from the application. Plex Serif headings, Plex Sans body, Plex Mono figures.

Structure: letterhead with tenant logo and contact block; document number, version, date, and validity; customer and site address; line items grouped by trade with an available-upgrades block set apart; tax breakdown by line with the registration number; holdback and payment terms when set; exclusions and assumptions as their own block; signature block.

**`quotes.pricing_display` decides how much arithmetic the customer sees** — `group_totals` by default (a total per trade, no quantities or unit rates), `detailed` (every line with quantity and rate, overhead and profit as their own lines), or `lump_sum`. Defaulting to `detailed` would have been wrong: most residential contractors will not send a homeowner a document reading `1,240.5 sqft × $4.00`, because it invites line-by-line negotiation of a price quoted as a whole.

**Available upgrades print their grossed-up price**, not the raw line total — the figure that matches what the customer is charged if they accept. See section 5.1.1 of the architecture spec.

A change order renders from this same template with a different heading, its own sequence number, and a reference to the quote it amends.

Print CSS requirements: `@page` margins, `break-inside: avoid` on line items so a row never splits across a page, repeating table headers on multi-page quotes, page numbering through Chromium's `displayHeaderFooter`, and the tenant logo inlined as a data URI so rendering never depends on an authenticated fetch.

Every string on the document comes from the `organization` record. Nothing is hardcoded.

## 8. Quality floor

Not features — the baseline the build is held to.

- WCAG 2.2 AA contrast on all text and interface boundaries. `ink-muted` at `#4A5A68` is the lightest text permitted to carry meaning.
- Full keyboard operation of the worksheet: Tab across, Enter to commit and descend, Escape to cancel an edit. Visible focus rings, never suppressed.
- `prefers-reduced-motion` respected; the margin gauge is the only motion and it stills.
- Every interactive element reachable and labelled for screen readers; the worksheet table is a real `<table>` with proper headers, not a grid of divs.
- No layout shift on recalculation. Figures update in place.
- Skeletons on first load, not spinners. Optimistic updates on line edits with rollback on failure.
